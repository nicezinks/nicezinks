# About Me

Hello! I'm a developer passionate about **software engineering, programming, systems, automation, web development and technology**.

I enjoy turning ideas into real applications and experimenting with different technologies to understand how things work behind the scenes. My main focus is building software that is not only functional, but also **organized, efficient, maintainable and pleasant to use**.

My primary development stack is centered around **Python, C, TypeScript and JavaScript**.

I use **Python** for application development, automation, tools, scripting, APIs, desktop software, prototypes and general-purpose development.

I use **C** when I want more control over the system, native Windows development, low-level functionality, performance-sensitive software, utilities and projects that interact more directly with the operating system.

I use **TypeScript** for modern applications that benefit from strong typing, maintainable codebases and scalable architectures.

I use **JavaScript** for web development, browser applications, interfaces, client-side logic and full-stack projects.

I also work with **HTML5 and CSS3** as part of my web development stack, creating interfaces that are responsive, clean and focused on usability.

My development interests include:

* Software architecture
* Desktop applications
* Automation
* System utilities
* Native development
* Web applications
* REST APIs
* Developer tools
* Performance optimization
* Cross-platform software
* Open Source projects
* Experimental projects
* UI/UX
* Real-world problem solving

I like taking an idea from a simple concept and turning it into an executable, usable and structured project.

---

#  Development Philosophy

I believe programming is more than simply making code work.

A good project should also be:

**Readable**
Code should be understandable and organized.

**Maintainable**
The project should be easy to modify and expand.

**Efficient**
Resources should be used carefully, especially in performance-sensitive applications.

**Reliable**
Errors, edge cases and unexpected situations should be considered.

**Usable**
Good software should be understandable from the user's perspective.

**Practical**
Projects should solve actual problems instead of being only demonstrations.

Because of that, I try to continuously improve my projects by testing features, fixing edge cases, simplifying implementations and refining the overall user experience.
